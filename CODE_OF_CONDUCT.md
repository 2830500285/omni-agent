# Code of Conduct

## Our Pledge

We want Omni Agent to be a practical and respectful open source project for people building, testing, and studying coding agents. Contributors and maintainers are expected to participate in a way that keeps technical discussion useful, evidence-based, and welcoming.

## Expected Behavior

Examples of behavior that helps the project:

- Be clear, direct, and respectful when discussing code, docs, tests, and design tradeoffs.
- Critique ideas and implementations, not people.
- Use evidence when making technical claims.
- Separate verified results from assumptions, experiments, or speculation.
- Accept that maintainers may reject changes that are too broad, unverifiable, unsafe, or outside the project scope.
- Help newer contributors understand terms such as runtime, eval harness, model profile, trace, approval boundary, and benchmark mode.

## Unacceptable Behavior

Examples of behavior that is not acceptable:

- Harassment, insults, threats, personal attacks, or discriminatory language.
- Publishing private information, secrets, tokens, logs, traces, or identifying details without permission.
- Deliberately misleading benchmark claims or attempts to present synthetic runs as real model performance.
- Repeatedly derailing technical discussions after maintainers have made a scope decision.
- Encouraging unsafe use of the agent, such as bypassing approval boundaries or exfiltrating data.
- Spam, low-effort promotional content, or unrelated advertising.

## Scope

This Code of Conduct applies to project spaces including GitHub issues, pull requests, discussions, documentation, examples, and any official community channel connected to Omni Agent.

It also applies when a person's behavior outside the project directly affects the safety, privacy, or participation of project contributors.

## Enforcement

Maintainers may remove comments, close issues, reject pull requests, restrict participation, or block users when behavior harms the project or its contributors.

For minor problems, maintainers may ask the person to clarify, edit, or stop the behavior. For serious or repeated problems, maintainers may take action without further warning.

If you need to report a conduct issue, contact the maintainer through GitHub. If the report involves a security or privacy issue, use the repository security reporting flow when available.
